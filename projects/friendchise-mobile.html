Mobile companion to FriendChise

FriendChise Mobile

A native operations app for frontline staff to move through shifts faster: find tasks, capture information with the camera, review procedures, and turn scanned inputs into structured work without opening a desktop dashboard.

What it complements

The mobile app is the shift-time front end for FriendChise. It reuses the same org-scoped backend and auth model, but strips away the desktop admin mindset so workers can act quickly while on the floor.

Fast access Tasks, tools, and org navigation are designed for short interactions and quick returns to work.
Camera-first capture Scan-to-Task accepts photos and PDFs, then turns them into structured drafts for review.
Shared backend Mobile calls the same FriendChise API, so task updates stay aligned with the web platform.

Overview

FriendChise Mobile is not a cut-down admin panel. It is the worker-facing side of the product, built around the moment someone needs to do something quickly during a shift.

The app keeps the interaction cost low: open the app, authenticate once, choose the organization, then move through tasks, tools, and scan flows without extra navigation. That is the difference between a system that looks complete and one that actually gets used on the floor.

Problem

In shift work, the real friction is usually not the absence of software. It is the time spent hunting for instructions, repeating manual steps, and asking the same operational questions over and over.

The mobile app is built to reduce that friction: surface the next task, keep procedures close at hand, and convert messy inputs like photos or documents into a structured action a worker can review and finish.

Mobile-First Workflow

1

Sign in and land in context

Authentication uses an OAuth-backed mobile flow with deep-link callbacks, then session state is restored so the app can return the worker to the right organization and route.

2

Open the task list

Tasks are surfaced in a searchable, paginated list with persisted view preferences so the app stays fast even when the same user returns many times in a shift.

3

Use tools instead of menus

The bottom bar keeps core actions close: Home, Tasks, and Tools. That makes the app behave like a shift utility, not a management dashboard.

↓
4

Capture information quickly

Scan-to-Task accepts camera images, photo library images, and PDFs. The flow is built for short interruptions, not long form entry.

5

Review before saving

The model output is never posted directly. The worker sees a draft, edits fields if needed, and confirms only after the result looks correct.

6

Return to work fast

Because the app reuses the same backend data, confirming a draft immediately refreshes the task list and keeps mobile and web in sync.

AI Utilities

Scan-to-Task

The main AI feature in the codebase. Workers capture a photo or select a PDF, and the app uploads that file to a temporary org-scoped storage path before asking the backend to extract structured task drafts.

Input: camera photo, library image, or PDF.

Processing: the backend normalizes file types, runs OCR / vision analysis where needed, splits content into chunks, and validates the generated draft shape.

Output: a draft with title, description, summary, source text, color, duration, people required, and wait-day bounds.

Review: the worker edits the draft, resolves validation errors, then confirms or discards it.

What I would not label as AI

The repo also contains a heuristic task-suggestion fallback, but that logic is rule-based rather than a separate AI product feature. I would not present it as AI on the portfolio page.

Use it as: supporting automation.

Do not use it as: a headline AI feature.

Mobile v1 note: the mobile app intentionally keeps Scan-to-Task narrower than the web flow. It supports one file at a time and skips the web app’s broader multi-file merge / duplicate adjudication UI.

Key Interactions

Task list and search

Infinite queries, debounced search, and persisted UI preferences keep the task view responsive without turning the screen into a desktop-style table.

Task creation

Workers can post a new task with structured fields, a rich description, and an optional org image picked from the camera or library.

Tools hub

The tools screen groups operational actions so scan-to-task sits next to the rest of the workflow instead of being hidden in a settings menu.

Session handling

Mobile auth stores the token securely, restores auth state on launch, and expires the session when the saved expiry time passes.

Org-aware navigation

The app keeps an organization context in route params and uses a bottom bar tuned for quick transitions between Home, Tasks, and Tools.

Camera and document capture

Scan input is normalized before upload, including HEIC/HEIF image handling, so the backend gets a usable file instead of a broken edge case.

The stack is intentionally practical: Expo Router for route structure, React Query for server state, Zustand for short-lived workflow state, SecureStore for auth persistence, and the same backend that powers the web product for business logic.

That combination matters because the mobile app is not trying to solve a different problem. It is solving the same operational problem with a smaller screen, a camera, and fewer taps.

Engineering Challenges

OAuth on a native app

Problem → browser redirects were not enough for mobile auth.
Decision → use an auth session, a mobile callback route, and secure token persistence.
Result → the app can hand off to Google / LinkedIn and return to the correct screen reliably.

Scan input that survives device quirks

Problem → iPhone photos and document uploads can arrive as HEIC, PDFs, or generic MIME types.
Decision → normalize the file on-device, validate size, and fall back to extension-based MIME detection.
Result → the backend receives files the vision pipeline can actually process.

Fast shifts, weak patience

Problem → workers do not have time for slow screens or repeated navigation.
Decision → keep the shell shallow, persist search and view state, and place tasks / tools in a fixed bottom bar.
Result → the app feels closer to a utility than to a management console.

Keeping mobile and web aligned

Problem → a task confirmed on mobile still has to behave like the same task in the web product.
Decision → reuse the same org-scoped backend and invalidate the same task queries after save.
Result → mobile stays in sync with the wider FriendChise platform.

Product Impact

The mobile app extends the existing FriendChise deployment to the device workers already carry during a shift. That is the real value: it reduces the need to walk back to a desktop, ask someone else, or retype information that already exists in a photo or document.
