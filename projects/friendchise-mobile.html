Overview

At Walker's Doughnuts, shift procedures and task tracking lived on paper or in whoever was on shift — the same gap FriendChise's web platform was built to close for managers at a desk. FriendChise Mobile brings that task and procedure system to staff who are on the floor with a phone, not sitting at a computer.

The app is used day-to-day on a shared device at the store via TestFlight. An App Store submission is in progress (the first review round required changes; a resubmission is underway) so staff can install it on individual phones.

What's AI, what isn't

OCR/vision extraction is a model call that runs server-side in the existing FriendChise backend pipeline. The mobile app's job is everything around that call: capturing and normalizing the file, uploading it, validating the returned draft's shape, and requiring a human review step before anything is saved — none of that review/validation logic is AI, and it isn't described as such.

OAuth on a native app

Problem → a plain browser tab can lose the "user activated" state across Google's multi-hop redirect chain, so the final redirect back into the app sometimes renders as a web page instead of returning control to it.
Decision → use ASWebAuthenticationSession (via expo-web-browser) instead of a Linking-based browser tab, with an attempt-ID guard so a stale OAuth attempt can't resolve after a newer one has started.
Result → Google and LinkedIn sign-in hand off back to the app reliably, including when a user restarts the flow mid-attempt.

HEIC photos the backend can't decode

Problem → iPhone photos (especially Portrait/Live/Burst shots) save as HEIC with embedded auxiliary images; the backend's HEIC decoder enforces a strict limit on those and rejects some files outright.
Decision → re-encode HEIC/HEIF to JPEG on-device with expo-image-manipulator before upload, and fall back to extension-based MIME detection for ambiguous file types.
Result → the backend only ever receives a format its vision pipeline can process.

Session expiry without decoding the token

Problem → the mobile session token is an encrypted next-auth JWE, so the client can't read its own expiry claims.
Decision → the OAuth callback persists expiry metadata alongside the token, and a background timer force-clears the session at that boundary rather than trusting the token's contents.
Result → session state stays consistent with the web app's session lifetime without any client-side token decoding.

Product Impact

The app runs day-to-day on a shared device at Walker's Doughnuts via TestFlight. Task creation and Scan-to-Task moved off paper and photo message threads into a task list staff already recognize from the web platform, so the record of what got done stays in one place instead of split across a phone's camera roll and a chat thread.

Per-staff installs are the next step once the App Store listing clears review, rather than everyone sharing one device.
