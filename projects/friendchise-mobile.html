Overview

Mobile context

At Walker's Doughnuts, shift procedures and task tracking lived on paper or in whoever was on shift, the same gap that FriendChise's web platform was built to close for managers at a desk. FriendChise Mobile brings that task and procedure system to staff who are on the floor with a phone, not sitting at a computer.

The app is live on the App Store. It started on a shared device at the store via TestFlight, and staff are moving onto individual phones now that the listing is public.

Reliability & Session Handling

OAuth on a native app

Problem

A plain browser tab can lose the "user activated" state across Google's multi-hop redirect chain, so the final redirect back into the app sometimes renders as a web page instead of returning control to it.

Decision

Use ASWebAuthenticationSession (via expo-web-browser) instead of a Linking-based browser tab, with an attempt-ID guard so a stale OAuth attempt can't resolve after a newer one has started.

Result

Google and LinkedIn sign-in hand off back to the app reliably, including when a user restarts the flow mid-attempt.

HEIC photos the backend can't decode

Problem

iPhone photos (especially Portrait/Live/Burst shots) save as HEIC with embedded auxiliary images, and the backend's HEIC decoder enforces a strict limit on those, rejecting some files outright.

Decision

Re-encode HEIC/HEIF to JPEG on-device with expo-image-manipulator before upload, and fall back to extension-based MIME detection for ambiguous file types.

Result

The backend only ever receives a format its vision pipeline can process.

Session expiry without decoding the token

Problem

The mobile session token is an encrypted next-auth JWE, so the client can't read its own expiry claims.

Decision

The OAuth callback persists expiry metadata alongside the token, and a background timer force-clears the session at that boundary rather than trusting the token's contents.

Result

Session state stays consistent with the web app's session lifetime without any client-side token decoding.

Network resilience on mobile connections

Problem

Uploads and scan requests can hang or get abandoned mid-flow on a spotty store Wi-Fi connection, and large files waste time if they're rejected only after a slow upload finishes.

Decision

Every API call goes through a shared fetch wrapper with a distinct AbortController reason for timeouts versus user cancellation, and Scan-to-Task checks the 15MB size cap on-device before any upload starts.

Result

Failures surface a specific, actionable message instead of a generic network error, and oversized files never leave the device.

Product Impact

Production Usage

The app started on a shared device at Walker's Doughnuts via TestFlight and is now live on the App Store. Task creation and Scan-to-Task moved off paper and photo message threads into a task list staff already recognize from the web platform, so the record of what got done stays in one place instead of split across a phone's camera roll and a chat thread.

Per-staff installs are rolling out now that the App Store listing is public, replacing the single shared device.
